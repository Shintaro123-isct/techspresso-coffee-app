# GitHub初期設定

## 初期状態（2026-10-20確認）

- Git、GitHub CLI、Node.jsはこのPCにインストール済み。
- GitHub CLIは未ログイン。
- 親フォルダーのGitにはコミット・リモートがない。旧Botや秘密設定が混在するため、そのまま全体をアップロードしない。
- Webアプリのフォルダーだけを独立したGitリポジトリとして扱う。
- ローカルmainを初期化し、共有対象を許可する`.gitignore`、手動テストworkflow、共同開発手順を準備済み。現段階でCloudflareへの公開設定はない。
- 持ち運べる模擬テスト88件とビルドをローカルで確認。既存の一括書込試験は開催日の固定日時を使うようにし、実行日によって期待値が変わらないよう修正した。
- 15分境界の日時保持は共有ソースだけで検証し、別フォルダーのシミュレーションとの照合は`TEST_WEB_SYNC=1`で明示したときだけ追加実行する。

## 本人が行うログイン

ターミナルで`gh auth login`を実行し、GitHub.com、HTTPS、ブラウザーでのログインを選ぶ。
ブラウザーの本人認証・権限確認を完了する。パスワード、トークン、確認コードを共有資料やチャットへ貼らない。
その後、アカウント名と接続状態だけを確認する。

## ログイン後に行うこと

1. 共有先（個人アカウントまたは指定されたOrganization）を確認する。
2. `techspresso-coffee-app`という非公開リポジトリ名が利用可能か確認する。
3. 追加対象のファイル一覧と機密情報検査結果を確認し、初回コミットとpushを行う。
4. GitHub上で非公開状態、main、ファイル内容を確認する。
5. メンバーの招待はGitHubユーザー名の指定後に実施する。
6. Actionsの無料枠とゼロ円予算を確認後、手動のApplication checksを実行する。

Cloudflare接続・本番切替・メンバー招待は初回pushとは別の操作である。
この手順書にリポジトリURLがない間は、GitHubへの公開が完了したと扱わない。

## 運用

お客様は商品・数量を選んでQRを提示。ここでは予約や支払いは確定しない。レジで内容・登録メニューの合計金額を確認し、現金受領チェック、実物の番号札を選んで確定する。画像読取と手入力も可能。

提供一覧は5秒ごとの取得成功時に更新。未提供の注文を古い順に表示し、基準超過は赤くする。実際に渡した杯を選んで確定。最後の杯は札を回収し、回収確認チェックを付ける。全杯提供した注文は非表示となる。レジの「会計へ戻った札」で実物を受領すると再使用できる。一括提供は2〜10札、1札の場合は単独提供APIを使用する。

QRには `v:1`、ランダムUUIDの `id`、`items:[{menuId,quantity}]` のみを含む。価格や個人情報は含まない。同内容の別客と再読取を区別するためのIDであり、署名・予約証明ではない。数量の編集そのものは防げないためレジで現物注文と金額を確認する。価格はレジ表示とサーバーの登録メニューから算出し、D1に現金・合計額を保存する。

同じQR IDをイベントの操作IDに使用する。同一内容・札での再送は1件だけ、同じQRを別札に付け直すことや内容変更は拒否する。取消・返却後も同じQRは再受付しない。新たに注文するお客様は新しいQRを生成する。番号札の重複はサーバーの原子的保存とrevision検証で防ぐ。

## 障害時

1. QRの不調・スマホなし: レジの手入力へ切替。
2. 保存の確認が30秒以内に取れない・提供画面へ出ない: 新規の電子登録を停止。受付側と提供側で札・注文IDを照合。
3. 保存結果不明のときは「同じ注文の保存確認」。ブラウザーを閉じても同じID・内容を端末保存し、再送する。別IDでの作り直しは禁止。
4. 復旧しない場合、責任者が紙へ切り替える。札・商品・杯数・時刻・現金受領を記載し、直接提供へ渡す。結果不明分は両者で重複確認して一度だけ作る。
5. 紙の注文は紙のまま完結し、復旧後に電子へ再登録しない。紙で使用中の実物札を電子画面で再使用しない。

お客様画面は最初の表示に通信が必要。Service Workerで公開注文ページだけを端末保存し、その後はオフライン再表示・QR生成が可能。キャッシュ削除、端末容量不足、プライベートブラウズなどで維持は保証できない。スタッフのAPIや注文一覧はキャッシュせず、古い保存状態を成功として扱わない。全アプリが停止した場合も紙と現金で営業する。
